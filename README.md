# NEXORA

### AI 기반 웹 보안 위협 탐지 및 통합 관제 플랫폼

NEXORA는 웹 서비스 운영에 필요한 회원·게시판·문의 관리 기능과 **보안 위협 탐지, AI 분석, 사고(Incident) 관리** 기능을 통합한 Java 웹 애플리케이션입니다. 웹 요청에서 의심스러운 패턴을 탐지하고, 관리자가 이벤트를 확인·분석하고 대응 상태를 관리할 수 있도록 구성했습니다.

> 이 문서는 저장소에 포함된 JSP, `web.xml`, 컴파일된 Java 클래스 및 보안 기능 문서를 바탕으로 작성했습니다. 실제 배포 환경에서의 정상 동작이나 성능 수치를 검증했다는 의미는 아닙니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | NEXORA |
| 유형 | 웹 보안 관제 및 관리 웹 애플리케이션 |
| 주요 기능 | 위협 탐지, AI 분석, 보안 이벤트/사고 관리, Slack 알림, 회원·게시판·문의 관리 |
| 아키텍처 | Java Servlet/JSP 기반 웹 애플리케이션, DAO/Service 계층 분리 |
| 데이터베이스 | MySQL |

### 개발 목적

- 웹 애플리케이션의 요청 단계에서 보안 위협 의심 패턴을 탐지합니다.
- 탐지 결과를 관리자가 확인하고 AI 분석을 요청할 수 있도록 합니다.
- 보안 이벤트와 사고의 이력 및 대응 상태를 관리합니다.
- 기존 웹 서비스 기능과 보안 관제 기능을 하나의 시스템으로 연결합니다.

## 3. 주요 기능

### 3.1 웹 보안 위협 탐지

- HTTP 요청에서 SQL Injection, XSS, 경로 탐색, 명령 삽입 및 SSRF 의심 패턴 탐지
- AI 입력에서 프롬프트 인젝션, 시스템 프롬프트 추출, AI 도구 오용 및 민감정보 입력 의심 패턴 탐지
- 규칙 기반 위험도 분류: `MEDIUM`, `HIGH`, `CRITICAL`
- 동일 출발지·규칙·경로의 반복 이벤트를 일정 시간 범위 내 집계
- 보안 이벤트 목록, 상세 정보 및 이력 확인을 위한 관리자 화면

### 3.2 AI 기반 보안 분석

- OpenRouter API 연동 모듈 구성
- 관리자 상세 화면에서 탐지 이벤트에 대한 AI 분석 요청
- 탐지 메타데이터를 활용한 분석 흐름
- 보안 이벤트 및 사고 분석 결과를 관리하기 위한 관련 서비스·DAO 구성

### 3.3 사고(Incident) 관리 및 알림

- 보안 사고 등록·조회·상태 관리 관련 기능 구성
- 사고 목록과 상세 화면을 통한 관제 흐름 제공
- Slack Webhook 연동을 통한 알림 기능
- 보안 기능 문서 기준 `CRITICAL` 이벤트 즉시 알림 및 일일 위협 요약 기능 명시

### 3.4 일반 웹 서비스 및 관리자 기능

- 회원가입, 로그인, 회원 관리
- 회원 탈퇴 및 탈퇴 회원 보존·정리 정책 관련 모듈
- 게시판 게시글·댓글·첨부파일 관련 모듈
- 문의 등록, 내 문의 조회, 관리자 문의 관리
- 관리자 대시보드, 회원·게시판·문의 관리 화면

## 4. 보안 및 데이터 보호 설계

저장소 내 보안 기능 문서에 다음과 같은 보호 정책이 명시되어 있습니다.

- 비밀번호 및 CSRF 토큰 필드는 탐지 검사 대상에서 제외
- 출발지 IP 원문 대신 SHA-256 해시 저장
- 탐지 근거의 저장 길이 제한 및 비밀번호·토큰·API 키 패턴 마스킹
- AI 분석 시 탐지 메타데이터만 전달하도록 제한
- CSRF 토큰 관리 및 비밀번호 해싱 관련 공통 모듈 구성

**범위 안내:** 현재 보안 감시 대상은 애플리케이션으로 유입되는 HTTP 요청과 AI 호출 경계입니다. 네트워크 패킷 검사, 외부 WAF 로그 분석 또는 네트워크 방화벽 기능은 포함하지 않습니다.

## 5. 프로젝트 구조

```text
teamproject1/
├── README.md
└── src/
    └── main/
        ├── ImportedClasses/          # 포함된 컴파일 Java 클래스
        │   ├── admin/                # 관리자
        │   ├── board/                # 게시판
        │   ├── common/               # DB, AI, 알림, 보안 공통 기능
        │   ├── inquiry/              # 문의
        │   ├── member/               # 회원
        │   ├── security/             # 보안 위협 탐지·분석
        │   └── sentinel/             # 사고 관리
        └── webapp/
            ├── admin/                # 관리자 JSP 화면
            ├── board/                # 게시판 JSP 화면
            ├── company/              # 회사 소개 화면
            ├── inquiry/              # 문의 JSP 화면
            ├── member/               # 회원 JSP 화면
            ├── solutions/            # 솔루션 소개 화면
            ├── index.jsp             # 메인 화면
            └── WEB-INF/
                ├── web.xml           # Servlet/Filter 설정
                ├── security-feature.md
                ├── sql/security_schema.sql
                └── lib/              # 포함된 라이브러리
```

> 업로드된 ZIP에는 Java 소스 코드(`.java`) 대신 `ImportedClasses` 아래의 컴파일된 `.class` 파일이 확인됩니다. 따라서 이 ZIP만으로 소스 수준의 수정·재빌드가 가능한지 별도 확인이 필요합니다.

## 7. 실행 및 환경 설정 안내

이 저장소는 일반적인 Spring Boot 프로젝트가 아닌 **Servlet/JSP 웹 프로젝트** 형태입니다. 실행 전 아래 사항을 확인해야 합니다.

1. Java 및 JSP/Servlet 호환 웹 애플리케이션 서버를 준비합니다.
2. MySQL 데이터베이스를 준비하고, 서버의 JNDI DataSource `jdbc/jspdb` 연결 설정을 확인합니다.
3. `src/main/webapp/WEB-INF/web.xml`에 정의된 Servlet·Filter 설정을 확인합니다.
4. 보안 기능 테이블을 자동 생성할 권한이 없다면 `src/main/webapp/WEB-INF/sql/security_schema.sql` 적용 여부를 확인합니다.
5. AI 분석과 Slack 알림을 사용하려면 서버 환경 변수에 필요한 값을 설정합니다.

```bash
OPENROUTER_API_KEY=<your-api-key>
OPENROUTER_MODEL=<model-name>
SLACK_WEBHOOK_URL=<your-slack-webhook-url>
```

**주의:** 실제 API 키, Webhook URL, DB 비밀번호 등 비밀값을 GitHub 저장소에 커밋하지 마세요. 위 값은 설정 항목을 설명하기 위한 예시입니다. DB 전체 스키마 및 실제 배포 절차는 별도 검증이 필요합니다.
